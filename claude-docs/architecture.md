## the dependency rule

`core/` depends on the c++ standard library and nothing else. `frontend/*` depends on core. `tests/` depend on core. dependencies point inward, never outward. any pr that adds an include of sdl, emscripten, or `<fstream>` inside `core/` is wrong by definition.

## core public api

the frontend sees one facade:

```cpp
class Gameboy {
public:
    bool load_rom(std::span<const uint8_t> bytes);
    void run_frame();                            // advances exactly 70224 t-cycles
    std::span<const uint8_t> framebuffer() const; // 160*144 values 0..3
    void set_button(Button b, bool pressed);
    size_t read_audio(std::span<int16_t> out);    // milestone 12
    // save/load state: milestone 13
};
```

palette mapping to rgb happens in the frontend. the core speaks color indices.

## tick model

the cpu is the master clock. one loop iteration = one instruction:

1. cpu executes one instruction (or services one interrupt), returns elapsed t-cycles.
2. `Gameboy` distributes that elapsed time: `timer.tick(t)`, `ppu.tick(t)`, `apu.tick(t)`, `serial.tick(t)`.
3. components raise interrupts by setting bits in `IF` through a shared `InterruptLine` reference.

instructions execute atomically (no mid-instruction memory timing) — a deliberate v1 accuracy decision, see overview non-goals. correct per-instruction totals, including branch taken/not-taken split, are still mandatory.

## patterns in use

- **facade**: `Gameboy` is the only type frontends touch.
- **mediator**: `Bus` mediates all component memory traffic; hardware address quirks live there and nowhere else.
- **strategy**: `Mapper` interface; `Cartridge` selects rom-only/mbc1/mbc3 from header byte 0x0147 at load.
- **template method, avoided**: no deep inheritance anywhere else; components are concrete final classes.
- **generated code**: the 512-entry decode table is generated by `tools/gen_opcodes.py` from the gbdev opcode json into `opcodes.inc`. regenerate, never hand-edit; hand-written helpers (alu, flag math) live in cpu.cpp and are unit-tested directly.

## interrupt wiring

`interrupts.hpp` defines the five bits and vectors. components hold `InterruptLine&` (a one-method struct wrapping `IF`), so `Timer` can request without knowing `Cpu` exists. dispatch order and the ei-delay live in `Cpu` only.

## frontend responsibilities (sdl)

event pump → `set_button`; `run_frame` → index buffer → rgb texture → present with vsync; audio ring fed from `read_audio`, and emulation pace is governed by keeping the queued-audio level in a target band once the apu exists. debug views (tile viewer, trace toggle) hang off the frontend, reading vram through a core debug accessor — never by including core internals.
